Handoff notes — R5 · R6
Policy data → Policy {preset: conservative|balanced|yield|custom, tests[14]{key, label, labelFi, op, threshold, unit, editable:true}} · verdict re-run is pure client math over engine-published deal metrics {actuals[14]} — no network on preset tap; save debounced 800 ms.
Explanation fields → each failing test: {failsBy, unit, fixablePrice?: 101700, fixableRent?: 859, fixable:false → reason:"building"} — banner copy is assembled from these, LLM never invents numbers.
Purchase → POST /checkout {packId, email, reportId} → Stripe confirm → webhook mints {account, credits, unlock} atomically; UI polls /unlock/:intent · declined codes mapped to plain Finnish/English · invoice fallback after 3 declines.
States → packs default (R6-1) · paying (button spinner, inputs locked) · paid (R6-2) · declined (R6-3) · 0-credits (R6-4) · first-free claim (banner path, no card).
Refunds → self-serve credit return + human-reviewed money-back, designed on R4 · R11.
A11y → preset pills = radiogroup; threshold steppers ±keyboard arrows; verdict banner aria-live assertive (it answers the user’s action); pay button announces amount.
Deferred frames — all rendered above: Conservative R5-4 · paying R6-6 · invoice fallback R6-7 · mobile success R6-8 · mobile declined R6-9.
Breakpoints → ≥1280 five-column test table, packs 3-across (R5-1/R6-1) · 768–1279 margin folds into sublines, packs compressed 3-across (R5-5/R6-10) · ≤767 failing tests sort first + bottom sheet editing, packs stacked (R5-3/R6-5).
